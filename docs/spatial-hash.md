# Spatial hash broad phase

Milestone 8 makes `BroadPhase::spatial_hash` the default in `CollisionSystem` and `PhysicsSystem`. `BroadPhase::naive` preserves the all-pairs reference and benchmark. Both feed the same primitive detector and impulse solver.

`SpatialHash` owns a map from signed integer `CellKey{x,y,z}` to collider indices. Hash collisions are resolved by key equality. Each tick rebuilds it from current collider storage and transforms, avoiding stale entries after movement, destruction, or swap removal. Sphere bounds use radius; box bounds use explicit half extents. Rotation and visual scale remain outside collision geometry, as in Milestone 6.

Cell coordinates are floor(position / cell size), including negative coordinates. Every cell intersecting a body's closed AABB is populated, with conservative float-roundoff padding. Default cell width is 3 world units; a positive finite width can be passed to either physics constructor. Width changes performance, not the intended contact set. Querying the cells occupied by collider i returns unique indices j > i. A stamp array eliminates duplicates before sorting each result; pair order matches the naive i/j traversal, preserving order-dependent sequential impulses. Results can contain false positives; the existing narrow phase resolves them. Query spans are invalidated by the next query or build, and the world must not be structurally changed between build and consumption.

Infinite planes take a global path. Finite shapes covering more than 4096 cells, invalid/nonrepresentable bounds, or cell coordinates outside ±1 billion also take that path. Global colliders are conservatively paired with every collider having a transform. This bounds per-body grid insertion and avoids coordinate conversion overflow without silently dropping large bodies or plane contacts. Missing transforms produce no hash candidates; static/static and unsupported shape pairs retain the narrow-phase filtering rules. Global and densely clustered scenes can still require quadratic work. Grid storage is proportional to occupied cells and inserted references; candidate scratch storage is at most O(N), not O(N²). No temporal coherence or multithreading is used.

Optional `CollisionStats` reports candidates, initial and correction checks, contacts, hash build time, query time, narrow phase, solver, and total collision time. Query timing includes cell lookups, duplicate removal, ordering, and filling the shared bounded pair batch. Broad phase is build plus query; total collision includes all stages and instrumentation gaps. Pair reduction is `100 * (1 - candidates / (N*(N-1)/2))` against all collider pairs, or zero for fewer than two colliders. In worlds with missing transforms, the reduction also reflects their omission. The separated-sphere benchmark has no such omissions.

Tests compare candidates against exhaustive primitive detection over seeded mixed shapes, negative coordinates, touching boundaries, varied sizes, three cell widths, infinite planes, huge-coordinate/large-shape fallbacks, missing transforms, and rebuilds after mutation. A mixed 102-entity falling-body scene runs 600 fixed ticks through both solvers and requires identical contact counts, positions, and velocities. Candidate uniqueness and ordering are checked directly. These checks preserve the existing supported-pair contract; they do not add CCD, friction, or unsupported collision types.
